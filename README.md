# Sekeron — Artist Intelligence & Recommendation

An evidence-led system that analyses artist profiles and supplied portfolio media, interprets incomplete hirer briefs, recommends relevant artists, and re-ranks them when new information arrives.


## Approach

1. Read the DOCX profile and classify every capability as demonstrated, claimed-only, conflicting or unknown.
2. Use category-specific dimensions from `src/schemas.py` rather than a generic artist score.
3. Interpret each conversation into explicit constraints, assumptions, contradictions and unknowns; then rank the two strongest plausible category matches.
4. Re-rank the matching original brief using the supplied follow-up and explain the ranking delta.

`artist_intelligence.jsonl` is intentionally evidence-rich: observations cite a profile or assessed-media filename. The model response is parsed as JSON and the program overwrites its media-selection field with program-generated selection metadata.

## Setup and run

Use Python 3.11+ and local Ollama with the configured model (`gemma4:e2b` by default).

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
ollama pull gemma4:e2b
python run.py
```
Install and start Ollama separately and make the required Gemma model available locally. No external API key is required.

The generated files are written to:

    outputs/artist_intelligence.jsonl
    outputs/recommendations.json
    outputs/updated_recommendation.json

## Media selection and video safety

The pipeline sends a maximum of three evenly distributed portfolio images for photographers and three evenly distributed audio files for musicians. It records supplied video files as unassessed media but sends no video file to Ollama and extracts no frames. Consequently, it makes no video-derived demonstrated claim. Video-editor records therefore use profile information as claim evidence only; capabilities that require media support remain unknown. This is an intentional evidence-integrity boundary, not a quality judgement about the artist.

## Implemented Choices

The implementation uses local Ollama with Gemma to avoid external API usage and keep the assessment reproducible.

The system prioritises demonstrated evidence over unsupported profile claims. It does not infer reliability, professionalism, popularity, character, or similar trust signals from portfolio material.

The follow-up re-ranking is implemented as a separate pipeline so that the original recommendation can be reused directly without re-processing the original hirer conversation.

## Evaluation

The generated outputs are checked for valid JSON structure and expected records. The artist intelligence output contains one record per artist, recommendations contain results for each hirer brief, and the updated recommendation contains the original and revised ranking together with the explanation for the change.

Final outputs are generated by the pipeline rather than manually edited.

## Limitations

The system is designed for the controlled assessment dataset rather than production use. Results depend on the supplied evidence and the capabilities of the local model. Video media is intentionally not analysed in this version, so video-derived demonstrated capabilities cannot be established. Incomplete or missing evidence is represented as uncertainty rather than being inferred.
